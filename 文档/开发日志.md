# 开发日志

> 本文件记录本系统从立项到当前的**每一次改动**。用途有三个：
>
> 1. 软著问询或答辩时，能说清每个功能是**什么时候、为什么**这么做的；
> 2. 两人分头开发时，各自能看到对方的进度，不用互相问；
> 3. 出问题时能顺着时间线回查是哪一次改动引入的。
>
> 与 `git log` 的关系：`git log` 是机器视角，本文件是人话版本。
> 每次提交都应在「三、改动明细」里对应一条记录。

---

## 一、怎么写

每完成一次改动，在「三、改动明细」里**最新日期的最上方加一条**，格式：

```
- HH:MM  **[分类]** 做了什么
  - 原因：为什么要改（是缺陷？是论文要求？是需求变更？）
  - 影响：改了哪些文件 / 哪些功能会受影响
  - 验证：怎么确认改对了
```

分类固定用这几种，便于检索：

| 分类 | 含义 |
|---|---|
| `功能` | 新增或调整业务功能 |
| `界面` | 页面、样式、交互 |
| `修复` | 改掉一个缺陷 |
| `材料` | 软著申请材料、文档 |
| `工具` | 生成/校验脚本 |
| `数据` | 数据模型、演示数据、标准库 |
| `协作` | 目录结构、分工、仓库配置 |

写的时候只写事实，不要写「优化了一下」「完善了细节」这类空话。
