# 开发日志

> 本文件记录本系统从立项到当前的**每一次改动**。用途有三个：
>
> 一、软著问询或答辩时，能说清每个功能是**什么时候、为什么**这么做的；
>
> 二、两人分头开发时，各自能看到对方的进度，不用互相问；
>
> 三、出问题时能顺着时间线回查是哪一次改动引入的。
>
> 与 `git log` 的关系：`git log` 是机器视角，本文件是人话版本。
> 每次提交都应在「三、改动明细」里对应一条记录。

---

## 一、怎么写

每完成一次改动，在「三、改动明细」里**最新日期的最上方加一条**，格式：

```
- HH:MM  **[分类]** 做了什么
  - 原因：为什么要改（是缺陷？是论文要求？是需求变更？）
  - 影响：改了哪些文件 / 哪些功能会受影响
  - 验证：怎么确认改对了
```

分类固定用这几种，便于检索：

| 分类 | 含义 |
|---|---|
| `功能` | 新增或调整业务功能 |
| `界面` | 页面、样式、交互 |
| `修复` | 改掉一个缺陷 |
| `材料` | 软著申请材料、文档 |
| `工具` | 生成/校验脚本 |
| `数据` | 数据模型、演示数据、标准库 |
| `协作` | 目录结构、分工、仓库配置 |

写的时候只写事实，不要写「优化了一下」「完善了细节」这类空话。

## 三、改动明细

### 2026-10-08

23:10  **工具** 新增免安装 exe 版：双击一个图标就能用（做法②单文件夹 + exe 启动器）

（一）原因：用户希望「像真的软件一样」给师兄用，且对方可能不会装 Python。讨论后选定做法②：保留文件夹形态（数据可备份、源码可核对、启动快），把 `启动（免安装）.bat` 换成一个带图标与版本信息的 exe 启动器。做法①（PyInstaller 单文件）要改数据目录、启动慢、易被杀软误报，暂不做。

（二）影响：

1）`工具/exe启动器.py`（被 PyInstaller 打包成 exe）：一个 tkinter 小窗口 —— 显示状态与实时日志、两个按钮（「打开系统」「停止并退出」）。流程是：找同目录 `portable_runtime\python.exe` → 跑 `seed_demo.py` → 跑 `run.py --no-browser`（浏览器由窗口开，避免开两个标签）→ 轮询端口就绪后自动打开浏览器；关窗口即结束服务进程。另外：**端口被占用时不再盲目跳过** —— 先探测是否是本系统（能返回登录页就直接开浏览器），若是别的程序占用则弹窗告知 PID 并询问是否结束它。全过程写 `启动日志.txt`（用户排错只需把这个文件发过来），并提供 **`--check` 无界面自检模式**（检查运行时、依赖、演示数据、服务、登录页，打印结果）。

2）`工具/打包exe.py`：用独立构建环境（`构建缓存/build_venv`，不污染本机 Anaconda）调 PyInstaller 打包启动器，带 `app/static/favicon.ico` 图标与版本信息（产品名、V1.0、项目组），产出 11.9 MB 的 exe。

3）`工具/装配exe版.py`：装配「一个包搞定」的目录并打 zip —— `01_提交材料`（两份提交用 PDF + 底稿）、`02_备查材料`（源程序全文 + 说明书 Word）、`03_运行版`（exe + 内嵌运行时 + 源码 + 使用说明 + 备用 bat）、`04_项目文档`（五份 Word）。

4）**踩到并修掉的两个坑**：① 打包成 exe 后标准输出可能是 GBK 代码页，`print` 中文（或含替换字符的文本）直接抛 `UnicodeEncodeError` 崩掉 → 启动器统一 `reconfigure(encoding="utf-8", errors="replace")`，并给子进程设 `PYTHONIOENCODING=utf-8`；② 我早前测试留下的孤儿服务一直占着 5000 端口，导致 exe 测试「启动成功但访问不到」的假象 → 启动器因此增加了端口占用检测与询问逻辑，测试脚本也改成按路径精确清理残留。

（三）验证（都在**把 PATH 清空、系统里找不到 python** 的环境下做）：
　　一、`exe --check`：运行时找到、依赖 OK（Flask 3.1.3）、演示数据写入（12 项标准/37 条规则）、服务就绪、**登录页 HTTP 200 且标题匹配**，返回码 **0**，无残留进程；
　　二、GUI 路径：双击 exe → 窗口出现、服务可访问；**模拟用户点窗口 X 关闭** → 启动器退出、**残留 python 进程 0 个、5000 端口已释放**；
　　三、最终包：解压后目录为四层 + 交付说明，`03_运行版` 2205 个文件 98.6 MB，压缩包 **52.9 MB**，首次运行自动生成 `app\app.db`（92 KB）与 `app\.secret_key`。

（四）**维护提示**：改了 `app/` 源码只需重跑 `python 工具/装配exe版.py`（exe 不打包源码，读的就是文件夹里的 app/）；只有改了启动器本身才需要重跑 `python 工具/打包exe.py --install`。

（五）交付包现状：`exe版`（52.9 MB，含材料 + 可运行软件，**推荐发师兄**）、`轻量版`（29.7 MB，需自备 Python，供留档或给有 Python 的人）。

### 2026-10-08

22:05  **材料** 修掉说明书的两个排版问题：数字被撑成「0 . 3」、目录点不动

（一）原因：用户对比说明书 PDF 与 Word 版，发现 PDF 里数字间距异常大（「0 . 3」「F = 0 . 7 4 0 4」「3 . 1 0」），而 Word 里正常；同时目录点击后不跳转。

（二）**问题一：数字被当成全角渲染**。根因在 `工具/make_manual.py` —— 它一直用 PyMuPDF 内置的 CJK 字体 `china-s` 出图，这个字体把 ASCII 当**全角**排版：实测 10.5pt 下「0.3」宽 **31.5pt**（三个字符各占一个全角），而宋体里只有 **15.75pt**。Word 版用的是宋体 + Times New Roman，所以看着正常 —— 两版字体不一致，PDF 才有这个毛病。
　　修法：改用系统里的真实中文字体（正文宋体 `simsun.ttc`、标题黑体 `simhei.ttf`），用 `fitz.Font` 测宽、`fitz.TextWriter` 写入（内置 `insert_text` 只认内置字体名，写不了系统字体）；找不到系统字体时自动退回内置字体并打印提示。
　　顺带踩到两个坑并解决：①`TextWriter` 每次调用都写一遍字体子集，PDF 从 2 MB 涨到 **29 MB** —— 改成每页累计一次写入，仍不够（字体整份嵌入），再加 `doc.subset_fonts()` 字体子集化 + `garbage=4`，回到 **2.18 MB**；②所有画线/插图前先落页文字，保持内容顺序。

（三）**问题二：目录点不动**。原来目录只是「画上去的文字」，没有任何链接。现在：
　　一、PDF 版：目录 26 条各自建立内部跳转链接（`LINK_GOTO` 指向对应章节所在页），并写入 **27 条 PDF 书签**（左侧大纲，含「目　录」）。逐条核对：26 条链接的目标页上都能找到该章节标题，异常 0 条。
　　二、Word 版：目录 26 条改为指向书签的**内部超链接**，正文每个标题处插入对应书签（共 26 个），外观仍是正文字体、不变成蓝色链接。踩坑一处：书签一开始插到了 `w:pPr` 前面，违反 OOXML「pPr 必须是段落第一个子元素」的顺序，改成插到 pPr 之后。

（四）验证：说明书 PDF **31 页 / 2.18 MB**、内嵌字体为子集化的 `SimSun` + `SimHei`、「0.3」宽度 **15.75pt**（与 Word 一致）、26 条目录链接全部指向正确页、27 条书签；Word 版用 Word 实际打开**无「内容有问题」修复提示**，31 页、29 张插图、26 书签、26 超链接；`check_materials` **22 项全部符合**、`verify_all` **19/19 通过**；渲染第 24 页与目录页肉眼复核，数字与目录都正常。送审包已按新说明书重打（100 个文件、10.5 MB）。
