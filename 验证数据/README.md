# 系统正确性验证数据

这套数据用来检验系统的**计算是否正确**。每个算例的期望值都先用论文公式
手工推算出来，再拿去和系统结果比对 —— 而不是"看系统算出什么就算什么"。

## 一、怎么用（两种方式）

### 方式 A：一条命令自动核对（推荐先跑这个）

```bash
python 工具/数值核对/验证用例.py
```

脚本会按网页的真实路径建好全部 8 个算例（建项目 → 建图斑 → 划分单元
→ 限制性判定 → 批量导入数据 → 执行评价），再逐条比对期望值，最后打印
推算式与实际结果。全部一致会输出「系统计算正确 ✓」。

算例**会保留在系统里**，可以登录后在界面上逐个查看：

| 项目编号 | 图斑 |
|---|---|
| VERIFY-01 … VERIFY-08 | 验证1 理想上限 … 验证8 一票否决 |
| VERIFY-05b、VERIFY-06b | 两个孪生对照图斑 |

清掉它们：

```bash
python 工具/数值核对/验证用例.py --clean
```

> ⚠️ **生成软著材料前请先执行上面的清理**。算例会出现在「项目与矿山档案」
> 「微地质单元」「适宜性评价」等列表页里，不清掉的话说明书截图会带上这一堆
> 验证数据，显得杂乱。

### 方式 B：自己在界面上手点（练习 + 核对）

每个 CSV 对应一个算例。以「用例 01」为例：

1. `项目与矿山档案` → `新建项目`，随便起名
2. 点该项目右侧的 `＋ 新建图斑`，随便起名、面积填 10
3. `微地质单元` → 该图斑 → `添加` 单元（类型与面积见下表）
4. `限制性判定` → 该图斑 → 五项**全部勾选通过** → 保存
   （用例 08 反过来，把「耕地属性」设为不通过）
5. `指标数据采集` → `批量导入（CSV / Excel）` → 选对应的 CSV → 导入
6. `适宜性定量评价` → 该图斑 → `开始评价`
7. 对照下表的「期望 F」与「期望等级」

> 算例 03 有三个单元，面积必须按 **2 / 5 / 3** 填，否则面积占比变了结果就对不上。
> 其余算例都只有一个单元，面积填多少都行（占比恒为 100%）。

## 三、每个算例的手算过程

### 算例 01｜理想上限 → F = 1.0000

输入：土石比 0.8、厚度 20、pH 7、有机质 30、8 种重金属全 0、
覆盖度 75、Shannon 0.7、坡度 25、坡向 阴坡

```
土壤：0.8/0.8=1，20/20=1，pH 7 落在 [5,9] 记 1，30/30=1，
      污染：8 种均为 0 → 各自 1-0/限值 = 1 → 污染 = 1
      土壤一级 = (0.25+0.25+0.17+0.17+0.17×1) / 1.01 = 1.01/1.01 = 1.0000
植被：75/75=1，0.7/0.7=1                        → 植被一级 = 1.0000
地形：坡度 25 ≤ 25 记 1，坡向 阴坡 记 1.0        → 地形一级 = 1.0000
单元 F′ = 0.44×1 + 0.31×1 + 0.25×1 = 1.0000
F = 1.0000 × 100% = 1.0000  →  适宜
```

> 注：土壤二级权重之和为 **1.01**（论文表 3 原值 0.25+0.25+0.17+0.17+0.17），
> 系统按实际权重和归一化，所以是 1.01/1.01 而非 1。

### 算例 02｜理论下限 → F = 0.0000

输入：土石比 0、厚度 0、pH 0、有机质 0、8 种重金属**全部取限值**、
覆盖度 0、Shannon 0

```
土壤：0/0.8=0，0/20=0，pH 0<5 → max(0-4, 0) = 0，0/30=0，
      污染：8 种均取限值 → 各自 1-1 = 0 → 污染 = 0
      土壤一级 = 0 / 1.01 = 0.0000
植被：0，0                                       → 植被一级 = 0.0000
单元 F′ = 0.54×0 + 0.46×0 = 0.0000
F = 0.0000  →  不适宜
```

> 这里特意用**平台**：平台不设地形指标，所以不会受"坡向最低只能到 0.2"的影响，
> 才能取到真正的 0 分。若换碎石边坡，最低也只能到 0.0165。

### 算例 03｜面积加权 → F = 0.4366

面积 2 / 5 / 3 ha，合计 10 → 占比 **20% / 50% / 30%**

```
岩质边坡：覆盖度 0、Shannon 0 → 植被 = 0
          坡度 25 记 1、坡向 阳坡 记 0.2
          地形 = 0.64×1 + 0.36×0.2 = 0.7120
          F′ = 0.45×0 + 0.55×0.7120 = 0.3916

碎石边坡：土壤五项全 0（污染取限值）→ 土壤 = 0
          覆盖度 75、Shannon 0.7        → 植被 = 1.0000
          坡度 90 记 0、坡向 阴坡 记 1.0 → 地形 = 0.67×0 + 0.33×1 = 0.3300
          F′ = 0.44×0 + 0.31×1 + 0.25×0.33 = 0.3925

平台：    土壤五项全取最优 → 土壤 = 1.0000
          覆盖度 0、Shannon 0 → 植被 = 0
          F′ = 0.54×1 + 0.46×0 = 0.5400

F = 0.2×0.3916 + 0.5×0.3925 + 0.3×0.5400
  = 0.07832 + 0.19625 + 0.16200
  = 0.43657  →  0.4366  →  基本适宜
```

### 算例 04｜污染取限值 → F = 0.9259

除污染外全部取最优，8 种重金属全部达到限值：

```
污染 = 0（8 种各自 1-1 = 0）
土壤一级 = (0.25+0.25+0.17+0.17+0.17×0) / 1.01 = 0.84/1.01 = 0.8316832
植被 = 1.0000，地形 = 1.0000
单元 F′ = 0.44×0.8316832 + 0.31×1 + 0.25×1 = 0.9259406
F = 0.9259  →  适宜
```

> **这个结果是论文权重的必然结果，不是 bug**：污染项权重 0.17、土壤一级权重 0.44，
> 所以重金属全部超标最多只让总分下降 0.17×0.44 ≈ 7.4%。
> 反过来说，重金属污染在论文口径里主要靠**限制性条件判定**把关
> （土壤污染一项不通过就直接不进入定量评价），而不是靠扣分。

### 算例 05｜岩质边坡忽略土壤指标 → F = 0.4896

CSV 里**故意填了完整的土壤数据**（土石比 0.8、厚度 20、pH 7、有机质 30、重金属 0），
但岩质边坡按论文表 3 不设土壤指标，这些值必须被忽略：

```
参与计算的只有：
植被 = 0.67×1(覆盖度75) + 0.33×1(Shannon0.7) = 1.0000
地形 = 0.64×0(坡度90) + 0.36×0.2(阳坡) = 0.0720
F′ = 0.45×1 + 0.55×0.072 = 0.4896
F = 0.4896  →  基本适宜
```

**怎么判断对错**：脚本会自动再造一个「**完全不填土壤数据**」的同型算例
（验证5b）作孪生对照 —— 两个算例的 F 必须**完全相同**。只要土壤数据
被漏算进来，两者就会分叉。

### 算例 06｜平台忽略地形指标 → F = 1.0000

CSV 里**故意填了坡度 90、坡向 阳坡**，但平台不设地形指标：

```
土壤 = 1.0000（五项全取最优）
植被 = 0.61×1 + 0.39×1 = 1.0000
F′ = 0.54×1 + 0.46×1 = 1.0000
F = 1.0000  →  适宜
```

**怎么判断对错**：脚本会自动再造一个「**不填坡度坡向**」的同型算例
（验证6b）作孪生对照 —— 两个算例的 F 必须**完全相同**。只要地形指标
被误算进来，两者就会分叉。

### 算例 07｜坡度分界与坡向赋值 → F = 0.7448

输入：覆盖度 75、Shannon 0.7、坡度 **57.5**、坡向 **阴阳坡**

```
植被 = 0.67×1 + 0.33×1 = 1.0000
坡度 57.5 > 25 → (90-57.5)/(90-25) = 32.5/65 = 0.5000
坡向 阴阳坡 → 0.6000
地形 = 0.64×0.5 + 0.36×0.6 = 0.3200 + 0.2160 = 0.5360
F′ = 0.45×1 + 0.55×0.536 = 0.45 + 0.2948 = 0.7448
F = 0.7448  →  适宜（刚好越过 0.7 分界）
```

### 算例 08｜一票否决 → 不产生评价结果

指标数据与算例 01 完全相同（理想上限），但把限制性条件判定里的
**耕地属性设为不通过**。

按论文 4.1 节，此类矿山**直接判定为「人工辅助或生态重建」，不进入定量评价**。

```
期望：点「开始评价」时被拦下并逐条提示原因，且不产生任何评价结果
```

## 四、等级边界

论文表 4 的分界口径是 **F<0.3 不适宜、0.3≤F<0.7 基本适宜、F≥0.7 适宜**，
边界值归属如下（脚本会自动核对）：

| F | 等级 |
|---|---|
| 0.2999 | 不适宜 |
| **0.3000** | **基本适宜**（含下界） |
| 0.6999 | 基本适宜 |
| **0.7000** | **适宜**（含下界） |

## 五、用到的公式（论文式(8)、式(9) 与表 3、表 4）

标准化结果一律限于 [0, 1]：

| 类型 | 公式 | 理想值/极值 |
|---|---|---|
| 越大越优 | `min(x / 理想值, 1)` | 土石比 0.8、厚度 20 cm、有机质 30 g/kg、覆盖度 75%、Shannon 0.7 |
| 越小越优 | `max(1 − x / 极值, 0)` | Cd 2、Hg 2、Pb 530、Cr 400、As 45、Ni 220、Cu 600、Zn 800（mg/kg） |
| pH 适中型 | [5,9] 记 1；>9 记 `max(10−x, 0)`；<5 记 `max(x−4, 0)` | — |
| 坡度 | ≤25° 记 1；>25° 记 `max((90−x)/65, 0)` | 分界 25° |
| 坡向 | 阳坡 0.2、阴阳坡 0.6、阴坡 1.0 | — |
| 污染 | 8 种重金属各自 `max(1 − 含量/限值, 0)`，等权平均 | — |

```
单元评价因子  F′ = Σ(一级权重 × 一级得分) / Σ(一级权重)
             一级得分 = Σ(二级权重 × 二级标准化值) / Σ(二级权重)
                        （不适用的指标不参与，权重也不计入分母）
整矿评价因子  F = Σ(单元面积占比 × F′)
```

## 六、数据文件

CSV 为 **UTF-8 带 BOM**，双击用 Excel 打开不会乱码；导入端按 `utf-8-sig` 读取，
两者都能用。列顺序与系统导入模板一致：

```
单元类型, 土石比, 土层厚度, pH, 有机质, Cd, Hg, Pb, Cr, As, Ni, Cu, Zn,
植被覆盖度, Shannon, 坡度, 坡向
```

空格表示该指标不适用（不填）。CSV 由 `工具/数值核对/验证用例.py --emit-csv`
从算例定义重新生成，与脚本里的期望值同源，不会各说各话。
