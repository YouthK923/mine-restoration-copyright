# 自然恢复软著
历史遗留废弃矿山自然恢复适宜性评价系统 V1.0 —— 计算机软件著作权登记项目

## 协作方式

本仓库只纳入**项目核心文件**（文档源文件、工具脚本、源代码）。
大体积二进制文件（参考模板 PDF、Word 产物、原始论文稿）不纳入版本控制，见下方"获取参考资料"。

## 获取参考资料（新成员必读）

以下文件不在仓库中，请从项目共享盘获取后放入工作区根目录：

- `变压器抗短路能力评估系统V1.0-说明书(1).pdf`、`...-代码(1).pdf` —— 软著材料格式模板 A
- `电网安全风险数据分析系统-用户手册.pdf`、`...-源代码.pdf` —— 软著材料格式模板 B（60 页源程序排版范式）
- `20261095_审改稿.docx（8.10）.docx` —— 论文初稿

> 这些是**只读参考件**，不参与协作编辑，因此不需要版本控制。

## 目录说明

| 路径 | 说明 |
|---|---|
| `软件著作权登记项目计划书_*.md` | 项目计划书（对外正式版，以此为准） |
| `软著登记申请材料形式要求_联网核实报告.md` | 软著材料形式要求的联网核实报告 |
| `_extract.py` | 从论文/模板中提取全文文本到 `_dump/` |
| `_mkref.py` | 生成 Word 中文排版模板（黑体标题、纯黑配色） |
| `_fix_heading_color.py` | 修正 docx 标题颜色 |
| `_ls.py` | 目录列表小工具 |
| `read_output.md` | 论文全文文本（便于检索） |
| `recalc.py` | 按论文 4.2 节方法重算案例得分 |

## 约定

1. **文档以 Markdown 为源文件协作**，Word/PDF 视为构建产物，需要时再导出。
2. 提交前先 `git pull --rebase`，避免冲突堆积。
3. 提交信息写清做了什么，不要用 "update" 之类的空话。
